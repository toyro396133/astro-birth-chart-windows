# גרסאות ועדכון אוטומטי — תהליך הפצה

## מצב ותנאים

מ־v0.2.0 יש מנגנון בדיקה והתקנה ל־Windows x64 בלבד.
היישום אינו יוזם חיבור רשת במצב ברירת המחדל; עדכונים אוטומטיים מחייבים
סימון אפשרות מפורשת. אפשר גם ללחוץ על "בדוק עדכונים" בכל עת.
נתוני הלידה אינם נכללים בבקשות לרשת, והתוכנה אינה מפעילה שירות ענן.

**הערת מעבר:** הגרסאות הישנות, ללא `AstroBirthChartUpdater.exe`,
אינן יכולות לעדכן את עצמן. יש להתקין את v0.2.0 (או גרסה חדשה ממנה)
פעם אחת ידנית, ולאחר מכן אפשר להפעיל עדכון אוטומטי.

## מבנה גרסאות

- גרסאות: `MAJOR.MINOR.PATCH` עם תג Git `vMAJOR.MINOR.PATCH`.
- מקור הגרסה היחיד בקוד: `src/astrochart/__init__.py`.
- תיאור חבילת Windows: `version.json` שנוצר בזמן הבנייה בלבד.
- ערוץ היציבות: `GET /repos/toyro396133/astro-birth-chart-windows/releases/latest`.
  גרסאות טיוטה ו־pre-release אינן מתקבלות, ואין חזרה לגרסה ישנה.
- הנכס המחייב: `AstroBirthChart-Windows-x64.zip`, עם תיקייה ראשית
  `AstroBirthChart/` וקבצים `AstroBirthChart.exe`,
  `AstroBirthChartUpdater.exe`, `version.json` ו־`_internal/`.

## פרסום גרסה

1. משלימים ביקורות וממזגים את PR #3, אחריו PR #4, ואחריהם את PR העדכון,
   לפי שרשרת הבסיסים. אין ליצור תג על ענף פיתוח.
2. מעדכנים את `__version__`, מריצים בדיקות ויוצרים commit ב־main.
3. יוצרים תג כגון `v0.2.0` המצביע ל־HEAD של `main` ודוחפים ל־GitHub.
4. `.github/workflows/windows-release.yml` מאמת שהתג תואם לקוד ומצביע
   ל־main העדכני, בונה EXE ומעדכן, מריץ בדיקות, בודק ZIP ויוצר GitHub Release.
5. GitHub מצרף `sha256` לכל קובץ Release ומפרסם אותו ב־API. הלקוח
   דורש חותמת תקינה וגודל תואם לפני כל חילוץ או התקנה.

דוגמה לפקודות **רק לאחר מיזוג וקבלה**:

```powershell
git checkout main
git pull --ff-only
git tag v0.2.0
git push origin v0.2.0
```

חשוב: בשלב זה **לא נוצרה עדיין גרסת Release**. קובצי ה־ZIP ב־GitHub
Actions הם ארטיפקטים של בדיקות, לא גרסאות המיועדות לעדכון אוטומטי.

## התנהגות העדכון

1. בדיקת גרסאות מתבצעת ברקע בפתיחת התוכנה אם התיבה מסומנת, או בלחיצה ידנית.
2. נמצא עדכון חדש? המערכת מורידה את ZIP דרך HTTPS ומאמתת את ה־SHA‑256
   מול חותמת GitHub Releases הבלתי משתנה ואת גודל הקובץ.
3. ZIP נבדק נגד קפיצת נתיבים, קבצים כפולים, קישורים, גודל וכמות חריגה,
   ומחולץ לתיקייה זמנית אחות לתיקיית ההתקנה (באותו כונן).
4. נדרשת החלטת משתמש להפעיל מחדש. רכיב העדכון העצמאי מועתק לתיקייה
   זמנית מחוץ למיקום התוכנה, ממתין לסגירתה ומבצע החלפת תיקיות.
5. הגרסה הישנה נשמרת כתיקיית `.astrochart-backup-*` לצד התוכנה.
   אם ההחלפה או ההפעלה הראשונית נכשלות, רכיב העדכון מנסה לשחזר.
   כשל מאוחר יותר לאחר הפעלה מוצלחת מחייב שחזור ידני מהגיבוי.

העדכונים פועלים ללא הרשאות מנהל רק כאשר תיקיית ההתקנה והתקייה
שמכילה אותה ניתנות לכתיבה. התקנה תחת Program Files עשויה להצריך
התקנה ידנית או העברה לתיקיית משתמש.

## אבטחה, פרטיות והפצה

- המודל משתמש ב־GitHub HTTPS ובחותמת ה־SHA256 של *אותו* GitHub Release.
  הוא מגן מפני שיבוש הורדה, אך אינו מספק חתימת מפתח עצמאית המגנה מפני
  פריצה לחשבון מפרסם. לפני הפצה ציבורית משמעותית מומלצים חתימות
  Authenticode או Ed25519 ממפתח פרטי שמנוהל מחוץ למאגר.
- אין שימוש במפתחות GitHub אישיים על מחשב הקצה.
- אין שמירת נתוני לידה בתוך תיקיית היישום. הגדרת העדכון בלבד נשמרת
  בתיקיית ההגדרות המקומית של המשתמש.
- אין התקנה כפויה או התקנה של Release לא מסומן.
- אין העלאה של נתונים או טלמטריה.
- קוד האפליקציה לא שוחרר ברישיון הפצה; יש להסדיר גם הודעות רישוי
  של Qt, Skyfield, pyluach ושאר התלויות לפני הפצה ללקוחות.
